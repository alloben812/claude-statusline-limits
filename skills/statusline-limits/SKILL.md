# Statusline: cost + rate limits (5h / 7d)

Статус-строка для Claude Code, которая внизу окна показывает:

```
Opus 5.5 (1M context)  my-project  ▇░░░░░░░░░░░░░ 9%  94k/1M  $1.28  2h12m  cache 92k  5h 4% 2h56m  7d 21% 5h56m
skills 2/74  stefania-wiki, statusline-limits
```

Первая строка: модель · папка · ctx полоской, % и занято/размер окна · $cost · длительность · cache · **лимит 5 часов в % и время до сброса** · **лимит 7 дней в % и время до сброса**. Вторая: skills.

Полоска рисуется фоном клеток, пустая часть заштрихована `░`. Клетка красится по своему месту: до половины зелёный, дальше жёлтый, оранжевый и к концу красный. Цифры процентов (ctx, 5h, 7d) берут цвет из той же шкалы. Строка `skills` показывает, сколько скиллов сработало в сессии из скольких доступно, и последние пять имён. Сработавшие скиллы ищутся в транскрипте сессии (вызов инструмента Skill и загрузка скилла командой, включая набранный `/имя`), плюс журнал плагина skill-tracker в `~/.claude/skill-log/`. Знаменатель даёт плагин (`.loaded-count`) плюс личные и проектные команды; без плагина видны только сработавшие скиллы.

Проценты 5-часового и недельного лимитов Claude Code отдаёт **нативно** в JSON статус-строки (`rate_limits.five_hour` / `seven_day`) — скрипт их только форматирует. Никаких внешних тулов (ccusage и т.п.) не нужно. Лимиты появляются только на подписочном тарифе; на API-биллинге эти поля пустые и блок 5h/7d просто не рисуется.

## Как это устроено

- `~/.claude/settings.json` → блок `"statusLine": {"type":"command","command":"bash ~/.claude/statusline-command.sh"}` — включает фичу.
- `~/.claude/statusline-command.sh` — сам скрипт: читает stdin-JSON от Claude Code через один `jq` и печатает готовую строку с ANSI-цветами.
- Зависимости: `bash`, `jq`. Больше ничего.

## Установка / перенос на новую машину

Спроси, ставим на текущую машину или переносим на другую — действие одинаковое.

Одной командой (репозиторий публичный):

```bash
curl -fsSL https://raw.githubusercontent.com/alloben812/claude-statusline-limits/main/install.sh | bash
```

Установщик: пишет `~/.claude/statusline-command.sh`, включает блок `statusLine` в `~/.claude/settings.json` (существующий settings бэкапит в `settings.json.bak.<timestamp>`, остальные ключи не трогает). После установки **обязательно скажи пользователю перезапустить Claude Code** — статус-строка подхватывается на старте сессии.

Если репозиторий склонирован локально — можно `bash install.sh` из папки клона (скрипт возьмёт соседний `statusline-command.sh`, без обращения к сети).

## Проверка (делай всегда после установки)

Прогони скрипт на мок-JSON и покажи пользователю результат — не отчитывайся «на словах»:

```bash
printf '%s' '{"model":{"display_name":"Opus 4.8"},"cost":{"total_duration_ms":3720000,"total_cost_usd":1.234},"context_window":{"used_percentage":42,"current_usage":{"cache_read_input_tokens":1200000,"cache_creation_input_tokens":300000}},"rate_limits":{"five_hour":{"used_percentage":37,"resets_at":'$(( $(date +%s) + 7200 ))'},"seven_day":{"used_percentage":61,"resets_at":'$(( $(date +%s) + 300000 ))'}}}' | bash ~/.claude/statusline-command.sh; echo
```

Ожидаемо: строка вида `Opus 4.8  [полоска] 42%  $1.23  1h2m  cache 1.5M  5h 37% 2h0m  7d 61% 3d11h`, в полоске 14 клеток; вторая строка `skills 0/N`, если стоит плагин skill-tracker. Проверь, что в `~/.claude/settings.json` появился ключ `statusLine` (`jq .statusLine ~/.claude/settings.json`).

## Диагностика

- **Статус-строки нет вообще** → не перезапустили Claude Code; либо в `settings.json` нет ключа `statusLine` (проверь `jq .statusLine ~/.claude/settings.json`), либо файл `~/.claude/statusline-command.sh` отсутствует / не исполняемый (`chmod +x`).
- **Нет блока `5h/7d`** → пользователь не на подписке (тогда поля `rate_limits` пустые — это нормально, cost по-прежнему виден), либо старая версия Claude Code без этих полей — обнови CLI.
- **`jq: command not found`** → поставь `jq` (`brew install jq` / `sudo apt install jq`) и запусти установщик снова.
- **Кракозябры / нет цвета** → терминал не поддерживает ANSI; на вывод не влияет, только на цвет.
- **Пустая часть полоски сливается с фоном или слишком яркая** → у терминала светлый фон: `export STATUSLINE_THEME=light`. Тему терминала узнавай у пользователя; системная тема macOS и профиль Terminal «по умолчанию» её не определяют (окна могут открываться другим профилем, см. `Startup Window Settings`).
- **Нет второй строки skills** → в сессии ещё не сработал ни один скилл и не стоит плагин skill-tracker (он даёт знаменатель). Скилл сработал, а строка его не видит → проверь, что в JSON есть `transcript_path` и файл читается.

## Кастомизация (правь `~/.claude/statusline-command.sh`)

- **Градиент полоски** — массив `RAMP` (палитра 256; truecolor не использовать, Apple Terminal его не умеет), число клеток равно длине массива (сейчас 14).
- **Остальные цвета** — переменные `C_*` рядом с `RAMP`; `C_TRACK` — штриховка пустой части.
- **Убрать/добавить сегмент** — в блоке `первая строка` закомментируй/добавь строку `seg+=(...)` (например убрать `cache` или `cost`).
- **Сколько имён скиллов** — `max` во второй строке (сейчас 5).
- **Формат таймеров сброса** — функция `fmt_left` (сейчас `3d11h` / `2h56m` / `42m`).

После правки скрипта перезапуск Claude Code не нужен — он вызывает скрипт заново на каждом обновлении строки.
